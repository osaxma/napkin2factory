## Verdict: NOT READY (four blockers; the seams themselves hold)

**What holds:**
- The contract is one object, read through registries: the core imports no domain by name. A fresh agent added a second domain with 0 core files changed (S-134, `gadget-2026-11-02.md:789`).
- The goldens are unchanged since v0.4. The v0.4 and v0.5 kiln outputs differ only by `choices.json`, the new rows and timestamps.
- Scope cannot hide a safety requirement, and the scope line agrees in `release.json`, the package cover and the report.
- An open choice stops `n2f release`, and `n2f check` never writes a decision.
- A wrong calc case fails, naming the calc, the expected value and the actual one.
- A newer schema stops with a plain message, and `n2f init .` snapshots before it migrates.
- The splits are within budget, and `make check-fast` is the land gate (2:09).

**What stops the release:**
- **B1:** `n2f impact` is not a superset of the rebuild for a field edit of an interface, a decision or a calc. One kiln interface edit is predicted as `['validate']`, but the build reruns 16 rules. A decision that decides a choice is predicted the same way, but the build reruns checks, report and site. The interface case already failed with v0.4's code; the decision case is a v0.5 path.
- **B2:** The contract gives a rule family no recording accessor, and the worked example misses a read. Changing a toy thing's `part` reruns only `validate`, so `build/toy/widget.json` keeps the old part. Every future domain copies this code.
- **B3:** A decided choice whose pick is not yet made in the model releases. The kiln shipped a BOM that still buys the M6 × 16 bolts the check found colliding.
- **B4:** The `core/data/*.yaml` open-set tables are hashed into no rule. Editing the driver words, which appear in 7 outputs, reruns nothing.

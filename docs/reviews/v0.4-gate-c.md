# Review gate C: architecture and honesty (napkin2factory v0.4, `main` @ 016689b)

**Verdict: NOT READY. Two blockers, both breaches of D5 (stale outputs). The rest of the architecture holds.**
What holds:
- Placement by interfaces works, and so does the alignment stage: a 10 mm shift fails, naming both occurrences and the distance.
- Ports are enforced, naming the file to edit.
- Hardware is counted and matches the BOM.
- The reach check catches a sibling read.
- `n2f context` is honest when nothing is built.
- `check --scope` leaves `build/checks/` byte-identical.
- `build --asm door` builds only the door.
- A product built from the v0.3.0 template gets the same evidence keys under v0.4 code as under v0.3 code.
- Promotion seeds stubs and budgets labelled computed.
- Every new kiln number is computed or flagged `[verify]`.

The two blockers:
- **(B1) The build plan cannot be a recorded read.** `bom://build-plan#…` does not parse as a URI, so every read of the plan is valued as a constant. Changing a unit's `driver:`, or renaming a part, leaves three things stale: the assembly sheet, the manual's `build_step()` text, and the report's build plan and joints sections.
- **(B2) The hardware stage reads `spare:` without recording it.** The checks rule records `asm://<id>`, not `asm://<id>#children`. Adding or removing `spare:` leaves a stale warn or a stale pass; the report showed "2 spare (two spares for the guards)" after the line was gone.

Both fixes are small, and each needs a regression test.

All runs were on copies under `<scratch>/gate-c/`: `kiln` (tracked, via `copy_product`), `nb` (unbuilt), `q3a–c`, `init-*`, `v03/`, `cart*`, `kiln-promote`. Nothing in the repo was changed; the golden tests ran with `-p no:cacheprovider`. `main` moved to a19a2e9 (S-116, transcript only) during the review. `git diff 016689b a19a2e9` touches no `src/`.

The design is right and the plumbing is not:

- the sheet records it (`assembly_sheet.py:283`);

**B2: hardware verdicts go stale.**

- The reverse also fails. With `spare:` removed, the rebuild still did not run checks, the row stayed `pass … 2 spare (two spares for the guards)`, and `index.html` still contained "two spares".

Other new paths:

- `resolve_interface` records every expression slug with `via` (`accessors.py:107-112`).
- `derive_build_plan` records its reads (`build_plan.py:39-51`).

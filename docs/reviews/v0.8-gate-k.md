`/Users/wakeel/napkin2factory-overseer/gate-k/` (copies of `examples/table`, `examples/test-stand`,

## Verdict: NOT READY

The store holds up: history only moves forward, redo after undo is the identity on the files, every
checkpoint stayed listed and restorable through undo, redo, rollback, `ecr abort` and `concept switch`,
edits saved by nothing get their own undoable checkpoint, undo stops at a change request's start, `close`
refuses a later edit and a red check, `refs/n2f/` never left the folder, and the schema 2 upgrade refuses
rather than guesses. Three things block the release, each one an owner reading a wrong thing as true. (1)
After a rollback the next change request reuses an id that a released Revision already names. (2) `ecr
impact` prints cost "(no change)" under "computed from the built design" for a 50 % longer oak top, because
the cost is the sum of fixed estimates. It also dropped v0.7's warning that geometry is not repriced, and
its JSON gives no basis for any figure. (3) `concept compare` and the board put the built design's total
mass in the napkin's "mass of the shapes" row. Eleven concerns go to the backlog.

## Blockers
1. **A change request id is reused after a rollback, even past a release.** In a clone of the released
   `table`: `N rollback 1`, then `N ecr start --title "Different change"` printed `✓ started ECR-001`, while
   `git show v1.0.0:CHANGELOG.md` has `## ECR-001 — Thicker top`. On `test-stand` the reuse moved
   `refs/n2f/ecr/ECR-001/baseline` from the aborted "probe" onto the new request. Wanted: an id names one
   change request forever. Where: `ecr/state.py:50-53` (`next_ecr_id` reads only the current `changes/`).
   Fix: take the highest id found in `changes/`, in the `refs/n2f/ecr/*` markers, and in every checkpoint's
   labels ("Started ECR-…"), plus a test: rollback, then start, gives a fresh id. DEC and card ids come from
   the same kind of current-folder scan; check them the same way.
2. **`ecr impact` labels an estimate as computed and calls an unrepriced cost unchanged.** The text reads
   `## The numbers (computed from the built design)` / `Cost: 1,014 USD → 1,014 USD (no change)` for a top
   800 mm longer and 22.9 kg heavier, whose cost is `basis: estimate`. The JSON `mass`/`cost`/`envelope`
   blocks give no basis. Wanted (N5, R6): each figure labelled, the cost as an estimate when any part's
   basis is estimate, naming the parts whose geometry changed but whose declared cost did not. Where:
   `ecr/live_text.py:36,62`, `ecr/live_impact.py:292` (empty note), against
   `core/graph/impact_reads.py:361-366`. Fix: add `"basis"` to each JSON block (mass and envelope
   `computed`; cost `estimate` when any BOM row's `cost_basis` is estimate). Print it per line ("Cost
   (estimate, from declared unit costs): …"), and list "changed shape, price not re-quoted: `top-board`".
   Apply the same label to the forked card's cost (`concepts/fork.py:277`).
3. **Compare and the board show the built design's total mass as "mass of the shapes".** `mass of the shapes
   … 9.86 kg (computed) … 15.8 kg (computed)` and `total mass … 16.5 kg (estimate) … —`. Wanted (R11): the
   built total in the total-mass row beside the napkin totals. Where: `concepts/fork.py:275`,
   `concepts/compare.py:67-73`, `concepts/board.py:78`. Fix: write the built mass under `total_mass` (fork
   and parked cells), and leave "mass of the shapes" empty for built cards. Add a test that a forked card's
   mass lands in the total-mass row.

## Concerns
1. The approval binding can be forged by copying the current hash into `approval.model_hash`; `close` then
   closed 40 mm when 36 mm was approved (`ecr/live.py:230`). Fix: compare against the hash of the tree of
   the "Approved ECR-x" checkpoint in the log (minus `changes/`, `model/signoffs/`), not the YAML value
   alone.
2. `concept switch` checks for unnamed folders before saving unsaved edits, so a new unsaved folder goes
   through (`concepts/switch.py:112` vs `:174`). Fix: check `vcs.files() ∪ vcs.unsaved_files()`.
3. A clone without `refs/n2f/` cannot restore a parked direction, though the card's `built.checkpoint` is in
   the log (`concepts/switch.py` preflight). Fix: fall back to that checkpoint when the marker is missing
   (the §7 risk-table fallback).
4. Parking a rejected card overwrites the owner's rejection reason and turns `rejected` into `parked`
   (`concepts/switch.py:206,241`). Fix: keep the earlier reason (e.g. `previously: …`), or park only the
   card that was the direction. C-001's seeded requirements (REQ-024 to 028) also stay live after switching
   back, with only a warning. Say which requirements came from the parked card.
5. The upgrade marks an `applied` request `aborted` while its edit stays in the model
   (`ecr/upgrade.py:199-200,219`), and does not report a cleared approval (ECR-004). Fix: map `applied` to a
   status that says it is in the model (or keep it open as R8 says), and print "approval cleared" for
   approved requests.
6. `ecr show` shows `approved` and the approved edits after the model changed, and prints a raw checkpoint
   hash (`cli/ecr.py:351`). Fix: print "approved, but the model changed since (run `n2f ecr impact`)" when
   the hash differs, and print `#n "label"` instead of the hex.
7. R12: tier 1's no-change build measured 2.2 to 2.6 s and tier 2's first one-parameter impact 22.0 s under
   one busy core, against S-270's 1.5 s and 9.1 s from single runs. Fix: before 0.8.0, record three runs on
   an idle host, and the 1.4 s import floor.
8. The property test lacks `ecr abort` and `concept switch` ops, which DoD 2 names, and runs only 10 × ≤7
   ops (`tests/unit/test_undo_properties.py:33-41,140`). Fix: add both ops.
9. `refs` reaches owner text and the `n2f_diff` MCP description (`cli/release.py:78`). The vocabulary test
   misses `refs` and skips `mcp/`, `core/*/` and `concepts/promote/`
   (`tests/unit/test_vocabulary.py:15-17,38-46`). Fix: "while building the Revisions", and widen the regex
   and the globs.
10. `docs/vocabulary.md:17` still lists `applied` / `n2f ecr apply`. The card template comment omits
    `parked` (`core/concept_render.py:81`). A forked card's note says "The envelope numbers are the model's
    current parameter values" over `envelope: {}`.
11. Schema errors for old fields are raw validator text (`Input should be …`, `Value error,`), and they do
    not say what the old state became. Fix: a message per retired state ("`applied` is gone in format 2: run
    `n2f init .`, or set `approved`").

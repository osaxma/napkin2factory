### Confusions / places the tool's docs or messages misled or stopped me

1. After `n2f concept switch C-001`, the switch output said:
   "C-001 fails its screening: … the arm's tip deflects 1.82 mm …" and
   "the model's parts are still C-002's, so a check judges those until the design changes".
   I expected `n2f check` under the C-frame direction to show that failure; it still judged the
   portal parts and exited 0. The C-frame failure is only in the switch output / concept screening.

2. After switching back with `n2f concept switch C-002`, the tool said:
   "brought back from when it was parked: style.yaml" and
   "the requirements changed since C-002 was parked; the next build checks it against them".
   It left REQ-026 (the C-frame's sag requirement) in the model, and the as-built card C-004
   became `rejected` instead of staying `exploring`.

3. `n2f status` has said throughout:
   "stage: Intake … ERROR (L1-measurable) model/requirements.yaml: [req://REQ-002] statement
   has no measurable value with a unit".
   Yet `n2f check` exits 0 (after sign-offs) and `n2f ecr close` succeeded. This mismatch made the
   gate look blocked when the requested build/check/ECR steps still worked.

4. `n2f ecr close` refused with a much longer requirement than the docs suggested:
   "ECR-002 cannot close: 1 check(s) fail (req://REQ-004); REQ-010 needs a human sign-off …
   REQ-011 … REQ-012 … REQ-014 … REQ-015 … REQ-017 … REQ-018 … REQ-019 … REQ-020 … REQ-021 …
   REQ-022 … REQ-023 … REQ-024 … REQ-026 …; fix the failing checks, rebuild, sign off what needs it,
   and close again".
   The docs say close needs "checks green"; I did not expect every human sign-off to be listed by close.

5. The first sign-off loop failed because the host shell is zsh, not bash:
   `for id in $ids; do n2f signoff "$id" …` passed the whole list as one argument and `n2f` said:
   "requirement REQ-010 REQ-011 REQ-012 … does not exist". I had to switch to a zsh array.

## What sent run 2 off course (n2f's side)
1. **The napkin overlap screen missed a frame kit.** C-004's cross member ran through the frame
   kit's member; `rough-shapes-overlap` compares blocks, plates and tubes only, so the card
   screened green and the seeded model failed "parts do not overlap" (50,388 mm³).
2. **A seeded requirement contradicted the owner.** REQ-008 "mass at most 33 kg" (the card's
   one-person lift limit) failed at 76.5 kg; nothing at the napkin said the card broke it.
3. **`n2f_sync` cut a validate error to a JSON fragment** (`"assemblies": 1, "interfaces": 0, …
   } }`), three times, so the agent could not see which field was wrong; it went to the source.
4. **`concept switch` failed nine times in a row**: a model problem (a parameter with a
   description key the schema refuses) reported once, then `engine_internal`
   `FileNotFoundError: model/parameters.yaml` (exit 70) while the agent was rewriting the file.
5. **No structure check after a change.** For 1800 mm the agent computed the sag by hand before
   asking the owner; the `structure` requirements exist only on seeded products, and the
   change's impact did not show the sag first.
6. **A switch keeps the old parts.** `concept switch` to C-005 and C-006 wrote requirements and
   decisions only; promotion seeds only an empty model, so the hand-edited parts stayed.
7. **Nothing checks that a part is held.** Neither the screens nor `n2f check` find a part that
   touches nothing below it, or legs that stop short of what they carry.
8. The sandbox let the agent install n2f from PyPI: the next run blocks package indexes, or the
   bar counts reads of an installed copy too (they are the same source).

Client notes (not n2f): question cards worked; dollar signs again rendered as maths; file cards
for the report and PDF did not open for the owner; the client's own tools showed red errors
(`spawn bash ENOENT`, a search key, "file has not been read").

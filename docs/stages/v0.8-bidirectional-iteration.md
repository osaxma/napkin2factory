## 0. Why this release
Hardware design goes backwards as often as forwards. Through v0.7 an owner can go forwards
(promote, build, change request, release) but the only way back is `n2f discard`, which throws
away everything since the last snapshot and cannot itself be undone. A promoted direction cannot
be swapped for another. A design change request carries its edit as a hand-made unified diff in
a `.patch` file, which agents get wrong. v0.8 makes every step reversible, lets the agent edit
`model/` files directly inside a change request, and reports what such an edit costs in mass,
price and sign-offs. It also ships the thin experimental MCP server and skill (Track D M0), so
outside users start trying the tool before v1.0 freezes its interfaces.

## 1. Mission, non-goals, definition of done
**Mission:** checkpoints and `undo` / `redo` / `rollback` on `core/vcs.py`; live draft change
requests (`ecr start | impact | approve | close | abort | quick`) in place of `.patch` files;
reversible promotion (`concept switch`, `concept fork-from-model`, `concept compare`); a build
with nothing changed that costs seconds, not ten; the guide and roles teaching all of it; the
thin MCP server and skill.

**Non-goals (stay in `BACKLOG.md`):**
- Merging two directions object by object.
- Switching direction after a release (a change request does that, R10).
- Several people editing one product folder at once.
- A hosted MCP service, and the composite MCP tools (Track D).
- The workbench (Track C). Its viewer milestones (C M1, M2) may run alongside, touching only `report/`.

**Definition of done (the macOS host plus the CI matrix, S-001):**
1. Every state-changing command leaves a checkpoint (R4). `n2f checkpoints` lists them in plain words with their vitals. `undo`, `redo` and `rollback` restore any of them, including edits made outside any command, and report every sign-off and approval they make stale (R5).
2. Restoring never rewrites history and never loses a saved state. Property tests enforce three things: redo after undo is the identity, rollback leaves every earlier checkpoint reachable, and abort is itself undoable (R2).
3. A design change request is edited in place. `ecr impact` reports added, changed and removed objects and files against the baseline, with before → after mass, priced cost (unpriced parts named) and envelope, plus every rebuild and invalidated sign-off (R6). An approval is bound to the model it approved, and `close` refuses after a later edit (R7).
4. Existing products upgrade with `n2f init .`. Schema 2 carries the change-request migration with its fixture and test. The kiln's three draft change requests migrate in `examples/` (R8).
5. `concept switch` parks the current direction and restores or seeds another with no lost work. It covers every row of the ownership table (§3) and refuses after a release or with a draft change request open (R10). `fork-from-model` puts the built design on the board as a card whose numbers are labelled computed from the built design (R11).
6. On tier 1 a build with nothing changed takes under 2 s, against 8 to 11 s measured in v0.7. One-parameter `ecr impact` and `undo` are measured and recorded (R12).
7. The guide, `roles/pm.md` and `roles/design.md` teach the new verbs within the token budget (road §2.1; 9,100 tokens measured at v0.7).
8. The MCP server and the skill ship as experimental (R14). `docs/reviews/prompt-set.yaml` exists, and the first should-trigger and should-not-trigger rates are recorded.
9. Gate B (Track B §4, the forward-and-backward trial on `examples/test-stand`) is passed by cold agents of at least two vendors. The benchmark oracle replays a change request (B-0218).
10. Gates K (engineering and honesty) and L (UX, owner persona) are closed with blockers fixed. The §2.1 measures are recorded, the health review done (S-190), version 0.8.0 set, pins `>=0.8,<0.9`.

## 2. Locked decisions (R-series)

| # | Decision | Why |
|---|---|---|
| R1 | **One store: `core/vcs.py`.** It gains these primitives:<br>• list snapshots with their messages<br>• read a file at a snapshot<br>• diff a snapshot against the unsaved working folder, by name and content (B-0060)<br>• hash the working folder without saving it (a temporary index, `write-tree`)<br>• restore a snapshot's tree into the folder<br>• create, move, read and delete named refs under `refs/n2f/`<br>Every caller in the package goes through these (D31). | Track B §1 assumed draft lines and restores that do not exist; today `Vcs` can only snapshot, tag, discard to HEAD and diff names (checked against the code at M0) |
| R2 | **History only moves forward.** Five operations restore a tree and then record a new snapshot equal to the old state: `undo`, `redo`, `rollback`, `ecr abort` and `concept switch`. HEAD never moves back, no branch is switched in an owner's folder, and Revisions stay immutable. A parked direction and a change request's baseline are named refs (`refs/n2f/parked/C-00x`, `refs/n2f/ecr/ECR-00x/baseline`), not draft lines. This amends Track B §1 and §3.3. | A folder switched to another line confuses `publish` (it reads the current line) and the agent's open files; linear history keeps undo derivable from the log and nothing is ever unreachable |
| R3 | **A checkpoint is a snapshot with a label.** Its message is the plain label. Trailers, which only `--json` shows, carry the vitals (mass and priced cost from a fresh build; "not measured" when the build is stale) and, for a restore, the state it restored (`Restores:`) and the checkpoint it undid (`Undoes:`). `checkpoints`, `undo` and `redo` read the log; no pointer file. Edits saved by nothing are saved first as their own checkpoint ("edits since …"), so `undo` undoes them and `redo` brings them back. | Track B §3.2: no second store; the trailers survive a fresh clone, a file in `build/` would not |
| R4 | **What checkpoints.** These commands checkpoint before they change anything: `promote`, `decide`, `signoff`, `ecr start` / `close` / `abort` / `quick`, `concept switch`, `concept fork-from-model`, `release`, `rollback`, `undo` and `redo`. `build`, `check` and the other napkin verbs never checkpoint (S-062). | A state change you cannot step back over is the bug this track fixes; a build that saves would flood the list |
| R5 | **What a restore covers.** A restore covers everything a snapshot saves; `build/` is not saved and goes stale through the manifest. After a restore, the command lists every sign-off and every change-request approval whose hashes no longer match (`core/checks/evaluators.py` `_signoff_state`, R7) and never revives one. Inside a draft change request, `undo` stops at the baseline; leaving the request is `ecr abort`. | Track B §3.2 rows "sign-offs" and "while an ECR is a draft" |
| R6 | **Live change requests.** `ecr start` records the baseline ref and the baseline's vitals in `changes/ECR-x.yaml` (`baseline:`), after saving any unsaved edits as their own checkpoint. `ecr impact` diffs the working folder against the baseline (R1) and rebuilds the current tree incrementally. It compares against baseline outputs kept in `build/changes/ECR-x/baseline.json`; when that file is missing, it rebuilds them from the baseline ref in a scratch copy (`worktree_add`, as `n2f diff` does). There is no `patch:` and no `apply` step. | The `.patch` file is what agents get wrong (Gate H B1, v0.6) |
| R7 | **Approval binds to the model.** `ecr approve` stores the working-folder hash (R1) beside the computed impact. `ecr close` refuses when the hash differs ("changed since it was approved; review the new impact") and when `build` or `check` is not green. | S-191: an approval not bound to what it approved |
| R8 | **Schema 2, the first real migration.** The change-request states become `draft → approved → closed` and `draft \| approved → aborted`. `rejected` stays readable as history, and `impact` and `applied` go away. The migration (`n2f init .`, `docs/schema-policy.md`) maps states as follows:<br>• `draft` or `impact` with a patch: a baseline is recorded and the patch applied over it.<br>• `approved` but not applied: becomes `draft`, approval cleared and reported.<br>• `applied`: becomes `approved`, bound to the current tree.<br>• `closed` and `rejected`: unchanged, with the patch file kept as history.<br>The card status gains `parked`. `migrate.py` `CURRENT` goes to 2; there is a `tests/fixtures/schema/v1` product with each state, and the kiln's three draft requests migrate. | A changed meaning is a bump (F7); one bump carries every v0.8 format change |
| R9 | **Old verbs bridge one version.** `ecr new` runs `ecr start` and says so once. `ecr apply` refuses and names the next step (`ecr approve`, then `ecr close`). Both bridges go in v0.9. | An agent following an old guide learns the new verb instead of failing blind |
| R10 | **Concept switch.** It follows the ownership table (§3). It parks the current direction's files as `refs/n2f/parked/<card>`, with the card's status set to `parked` and a note of its built mass and cost. It then restores the target's parked files or, for a card never promoted, runs the normal promotion seeding. Requirements changed since parking are re-checked on the first build. It refuses after the first release (a direction change then is `ecr start --kind design`) and while a change request is a draft. Restores are by file, not by object. | Agents rewrite model files wholesale (v0.7 handoff): an object-level merge would guess; file-level restore is exact |
| R11 | **The built design on the board.** `fork-from-model` refuses on a stale build. It writes a card whose envelope, mass and cost are labelled `computed` with the source "from the built design", and the board marks built cards apart from napkin ones. `concept compare` prints the same table; `--json` carries it. | N5: every number says where it comes from |
| R12 | **Measured, not claimed.** Each wave boundary records the §2.1 measures plus four timings on tier 1 and tier 2, warm: a build with nothing changed, a one-parameter `ecr impact`, `undo`, and `concept switch`. The target is 2 s for the first and is set from the first measurement for the rest. | The v0.7 handoff: tier 1's no-change build is 8 to 11 s, and every loop in this track pays it |
| R13 | **The count.** M1a, M1b, M2 and M3a are planned core work and list their `core/` files in the commit body. M1c names its files when profiling finds them. M4 and M5 are expected to touch 0 core files. | Road §5.5 |
| R14 | **MCP and skill, experimental.**<br>• The server is an optional extra (`napkin2factory[mcp]`).<br>• Its tools are generated one to one from the CLI's verbs, passing `--json` through, so a verb added later appears without an edit.<br>• Its description says once that the tools change before 1.0.<br>• The skill is a plain `SKILL.md` inside the package, installed as the guide's "Adapting to your client" says, with a fallback for clients without skills.<br>• `n2f init` writes neither. | Track D M0; the generic rule (S-076, S-077): nothing `n2f init` writes depends on one client |
| R15 | **Backward compatible but for R8.** A v0.7 product opens after `n2f init .`. The examples and fixtures are migrated, not hand-edited, and goldens are regenerated with a logged reason. | Road §3.1 |

## 4. CLI surface added or changed
New verbs:
- `n2f checkpoints`, `n2f undo`, `n2f redo`, `n2f rollback <checkpoint | ECR-x | v1.0.0>`.
- `n2f ecr start | abort | quick`.
- `n2f concept switch | fork-from-model | compare`.

Changed verbs:
- `ecr impact` diffs live.
- `ecr approve` binds to the model hash.
- `ecr close` checks that hash.
- `ecr new` and `ecr apply` bridge (R9).
- `n2f discard` becomes undoable: it saves the edits it drops as a checkpoint first.

Every `--json` carries the checkpoint id. No git word reaches owner-facing text (`docs/vocabulary.md` gains "checkpoint"; B-0121).

## 7. Risks
| Risk | Watch | Fallback |
|---|---|---|
| A restore loses work | R2, R3: every restore checkpoints first; property tests; the folder's earlier states stay reachable by ref and log | `n2f rollback` to the checkpoint before the restore |
| Refs under `refs/n2f/` leak through `publish` or vanish in a clone | M1a tests both: `publish` sends its own line only; a fresh clone without the refs reports what it lacks instead of failing | Record parked directions as checkpoints too, so the log alone can restore them |
| A folder copied without its history | `undo` says the folder has no history and names `n2f init .` | — |
| `ecr impact` is slow on tier 2 | R12's timings at each wave | Cache the baseline outputs (R6) and rebuild only the touched set |
| The guide outgrows its budget | M4 measures it | Move detail to `docs/cli.md`, which the guide links |
| The migration breaks an owner's open change request | M2c's v1 fixture holds every state | Old states stay readable; the migration refuses with the request's id instead of guessing |

## 8. How the overseer runs this plan
As `v0.7-everyday-breadth.md` §8, with these differences:
- At most two of the overseer's own subagents at once, until the maintainer raises it; agy workers for well-specified tasks (M2a, B-0259, M4.0's fixtures).
- Wave 1's four tasks have disjoint files. Run two at a time, M1a first, because wave 2 waits on it.
- Each brief carries R13's rule. After each wave the overseer records the `core/` count and R12's timings.
- Gate B and the re-derivations use a different vendor's model from the one that built the verbs.
- Push only when the maintainer asks.

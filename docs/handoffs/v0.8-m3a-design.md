## The card's built figures (seam)
`ConceptCard.built: BuiltDesign | None = None`, written only by M3a's verbs and left out when None:
```yaml
built: {event: parked, checkpoint: 3f2a…, number: 14, mass: 23.1 kg, cost: 180 USD, at: 2026-11-06T10:12:00}
```
`event` is `forked` (the card was made from the built design) or `parked` (a switch set the
direction aside). `mass` / `cost` are the strings `core/vitals.current_vitals` gives (None:
not measured, a stale build). `checkpoint` is the saved state the figures were measured on,
`number` its checkpoint number. Schema 2 is not released yet, so the optional field joins it
without a new bump (`docs/schema-policy.md`; recorded in the M3a decision entry).

## `n2f concept switch <card> [--fresh] [--override --reason "…"] [--by NAME]`
Order, all or nothing (any refusal or failure after the first write restores the folder to the
saved state taken in step 2 and removes a marker it created):
1. **Refuse** (exit 3, `GateBlocked`, nothing written): no saved history; a Revision exists
   (`Vcs.tags()` non-empty; `ecr/release.py` is the only writer) → a direction change is now
   `n2f ecr start --kind design --title "…"`; a change request is open (draft or approved,
   `ecr/checkpointing.open_change_request`) → finish it or `n2f ecr abort ECR-x`; no recorded
   promotion (`core/concepts.recorded_promotion`) → `n2f concept promote`; the target is the
   current direction; a tracked folder §3 does not name (below); a parked target whose marker
   is missing (a copy made elsewhere) without `--fresh`.
2. Save unsaved edits as their own checkpoint (`save_edits_first`, R4).
3. **Park** the current card: marker `parked/<current>` → the current saved state
   (`Vcs.set_ref`; moved if it exists, never deleted by a switch, so `undo` of a switch finds it
   again). The card: `status: parked`, `decision: {reason: "parked when C-00y was chosen
   (DEC-0zz)", at}`, `built: {event: parked, …}` from `current_vitals`.
4. **Bring the target**:
   - parked with its marker (and no `--fresh`): `Vcs.restore(marker, paths=<direction paths>)`,
     file by file (R10). A decision is appended to `model/decisions.yaml`: "Design direction
     back to <title>", context names the parked card and its figures, the decision text says
     it supersedes the current card's `decision.dec`, `links: [dec://<that>]`.
   - never promoted (exploring or rejected), or `--fresh`: the normal promotion
     (`concepts/promote.promote(..., snapshot=False, supersedes=<current dec>)`) seeds the card
     into the model as it is: the parked direction's parts stay until the owner changes them,
     and the result says so in one line. Promotion's own gates apply (built, green or
     `--override --reason`, conflicting parameters need `--override`). `supersedes` adds the
     superseded decision to the new decision's context and `links` (`dec://DEC-0xx`).
   The target card: `status: promoted`, `decision: {dec: <new DEC>, at}`, `built` removed.
5. **Validate** (`core/loader.validate`); errors → restore, refuse with the first problems in
   plain words (a requirement that checks a part the target does not have is the likely one).
6. **Checkpoint** `Switched to C-00x (<title>); C-00y parked`. Then list
   `stale_after_restore` lines, and one line when `model/requirements.yaml` differs from the
   parked state's ("the requirements changed since C-00x was parked; the next build checks it
   against them", R10).
Words and `--json`: the switched-to and parked cards, the decision id, the checkpoint (id and
number, §4), the files restored or the parameters and requirements seeded, the stale lines.
No git words (`docs/vocabulary.md`): "saved state", "checkpoint", never ref/commit/branch.

`concept promote` (verb.py): when another card is the chosen direction, its refusal names
`n2f concept switch <card>` before the first release and `n2f ecr start --kind design --title
"…"` after it (this is "the lockout becomes R10's refusals").

## `n2f concept fork-from-model [--title "…"]` (R11)
Refuses when the build is out of date with the model (any rule but the renders would run,
`core/graph/runner.explain_build(product, "all", render=False)`) → "run `n2f build`, then
fork". Saves edits first, writes the next card (`exploring`, `based_on` the chosen card when
there is one) and checkpoints `Forked C-00x from the built design` (R4). The card:
- copies `layout`, `site`, `style`, `modules`, `massing` from the chosen card; `envelope` the
  chosen card's keys with the model's current parameter values (`promote/parameters.seed_plan`
  names each entry's parameters; an entry whose parameters are not all in the model keeps the
  card's value and says so in `notes`);
- `screening.computed`: `width`, `depth`, `height` (the top assembly's bounding box from the
  build), `mass`, `cost` (the parts list's total), each `label: computed`, `source: "from the
  built design (checkpoint #14)"`; `rules`: one `fail` row per requirement the last
  `n2f check` failed; `verdict` red when there is one, green otherwise;
- `built: {event: forked, …}`; `notes` says where it came from.
`concept build` refuses a forked card: "make a variant to explore it: `n2f concept new
--based-on C-00x`" (a variant copies the card's sections, not `built` or `screening`).

## `n2f concept compare [cards…]` and the board (R11)
`compare` prints one table: a row per value (the board's names, units and labels, the cost
rows, the verdict), a column per card (default: every built card); a forked card's column says
"from the built design", a parked card's shows its built mass and cost "when parked". `--json`
carries the same rows. The board marks a forked card apart from napkin ones (a "from the built
design" mark) and shows a parked card's figures; `cost` joins the board's strip.

# Re-seeding on a Concept Switch (B-0329)

## 1. Switch and Promotion Code Today

### (1) What a switch does today to model files, step by step
In `src/napkin2factory/concepts/switch.py` (`switch`, `_preflight`):
1. Preflight verifies change tracking exists, no open change requests, no released Revisions, target is not current, unnamed files check passes, `model/parameters.yaml` is valid YAML, and the model validates.
2. Unsaved edits are saved first as their own checkpoint (`save_edits_first` in `ecr/checkpointing.py`).
3. Current direction is parked: marker `refs/n2f/parked/<id>` is set to start checkpoint `start.id`, and `concepts/<id>.yaml` is updated to status `parked` with `built` pointing to `start.id` (`cm.update_card_status`).
4. Route dispatch:
   - Restored route (`_restore`): restores `direction_paths()` from the parked snapshot (`Vcs.restore`) and appends a decision to `model/decisions.yaml`.
   - Seeded route: calls `promote()` in `concepts/promote/verb.py` (`snapshot=False`, `supersedes=old_dec`). Because `product.parts` or `product.assemblies` already exist, promotion leaves the earlier parts and layout untouched and appends only parameters, style, requirements, and a decision.
5. Saves a checkpoint `Switched to <target> (<title>); <parked> parked` (`checkpoint` in `ecr/checkpointing.py`).
6. Identifies stale sign-offs and approvals via `stale_after_restore()`.

### (2) What promotion's seeding writes, and what it requires to be empty
- Seeding writes:
  - `concepts/promote/seeding.py` (`plan_seed`, `_assemblies`): part definitions in `model/parts/<pid>.yaml`, geometry layout in `model/geometry/<aid>.py`, assembly definitions in `model/assemblies/<aid>.yaml`, driving sizes and stretch gap parameters in `model/parameters.yaml`.
  - `concepts/promote/modules.py` (`plan_modules`): top assembly and module stubs in `model/assemblies/<aid>.yaml`.
  - `concepts/promote/verb.py`: structure requirements (sag and strength factors) in `model/requirements.yaml`.
- Requirements to be empty:
  - `plan_seed()` requires `product.parts` and `product.assemblies` to be empty (`if product.parts or product.assemblies: plan.skipped = ...`).
  - `plan_modules()` requires `product.assemblies` to be empty.
  - `plan_seed()` and `promote()` require that none of the generated files exist on disk (`GateBlocked`).
  - `plan_parameters()` requires envelope parameters not to conflict with existing values unless overridden.

### (3) Where switch calls seeding, and what must be set aside first
- Call site: In `switch()` in `concepts/switch.py` at step 4 (the seeded route, when target is not parked or `--fresh` is passed), replacing the current call to `promote()`.
- Set aside first: All files under `direction_paths()` (`concepts/direction.py`): `model/parts/`, `model/geometry/`, `model/assemblies/`, `model/interfaces/`, `model/calcs/`, `model/docs/`, `model/tests/`, `model/signoffs/`, `style.yaml`, and direction-specific parameters in `model/parameters.yaml`.
- Restoring earlier model: Steps 2 and 3 save loose edits and capture the full active state at `start.id` under marker `refs/n2f/parked/<current_id>`. `n2f undo` restores the pre-switch checkpoint (`start.id`), bringing back all files. A switch back calls `_restore()`, which restores `direction_paths()` from `start.id` exactly as parked.

## 2. Hand Edits, Change Requests, and Sign-offs

### (4) Hand edits made to the earlier model
- Kept with that card: `save_edits_first()` saves loose edits to a checkpoint before parking. The snapshot `start.id` stored under `refs/n2f/parked/<id>` and recorded in `built.checkpoint` of `concepts/<id>.yaml` contains every hand-edited file.
- How restored: `n2f undo` reverts to `start.id` across the entire workspace. Running `n2f concept switch <earlier_card>` calls `_restore()`, pulling all `direction_paths()` from `start.id`.

### (5) Invalidation of change requests and sign-offs, and telling the owner
- Change requests: `_preflight()` blocks switching if any change request is open. For approved change requests, `stale_after_restore()` detects when the approved model hash no longer matches the folder and invalidates the approval.
- Sign-offs: Direction sign-offs in `model/signoffs/` are set aside with the earlier model. Any remaining sign-offs whose check rules or evidence no longer hold are flagged as invalid by `stale_after_restore()`.
- Owner notification: The CLI prints yellow warning lines prefixed with `!` for each stale approval and invalid sign-off. Under `--json`, `stale` contains the plain-words messages.

## 3. Proposed Change and Risks

### Proposed change (9 steps)
1. Preflight baseline check (`concepts/switch.py`): verify a pre-promotion baseline snapshot exists in change history.
2. Save loose edits and park current card (`concepts/switch.py`): run `save_edits_first()`, set `refs/n2f/parked/<current_id>` to `start.id`, and mark card `parked` with `built.checkpoint`.
3. Set aside direction files (`concepts/switch.py`): restore `direction_paths()` to the pre-promotion baseline snapshot using `Vcs.restore(baseline_id, paths=direction_paths())`.
4. Clear earlier card requirements (`concepts/switch.py`): remove requirements tagged `card-field:` or sourced from the parked card from `model/requirements.yaml`.
5. Seed new model (`concepts/promote/verb.py`, `concepts/promote/seeding.py`): run promotion seeding into the clean model, writing parts, assemblies, geometry, and driving parameters from target's rough shapes.
6. Update target card (`concepts/switch.py`): mark target card `promoted` with the new decision id and clear `built`.
7. Validate model (`concepts/switch.py`): run `validate()`; on any error, restore folder from `start.id` and revert the parked marker.
8. Record switch checkpoint (`concepts/switch.py`): save checkpoint `Switched to <target_id> (<title>); <parked_id> parked` with vitals from the new build.
9. Report stale notices (`concepts/switch.py`, `cli/concept_switch.py`): run `stale_after_restore()` and output stale approvals and sign-offs.

### Risks
- Baseline snapshot resolution: folders with truncated or non-standard history might fail to locate a clean baseline.
- Lingering requirements: if earlier card requirements are not fully cleared, they may contradict target card screening limits.
- Seeding failure rollback: invalid rough shapes that fail composition or validation during seeding require atomic rollback to `start.id`.
- Domain family references: interfaces or wiring in external domain folders could reference parts that were set aside.

## 4. Tests Needed
- Switch to unpromoted card removes earlier parts and writes new parts, assemblies, and layout geometry.
- Switch back to parked card restores earlier parts, layout, and hand edits exactly.
- Undo after switch brings back the earlier model and its hand edits across all files.
- Switch to card with different envelope dimensions updates driving parameters without conflict.
- Old card-specific requirements are replaced by target card requirements.
- Earlier sign-offs and change request approvals become stale after re-seeding.
- Switch with `--fresh` re-seeds from sketch even if a parked direction exists.
- Failed validation during re-seeding rolls back the model to the state before switch.

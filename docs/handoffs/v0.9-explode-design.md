# v0.9 M1: exploding each unit along its own direction (design, before the build)

Q2 (S-290): the maintainer wants a classic exploded view in v0.9, not the one-axis rank. This note says
where a unit's direction comes from; the build waits for the maintainer's reply to the questions at the
end. Facts below come from reading the code (file:line, 2026-11-07, at 7ce83f8) and are to be re-checked
by whoever builds it.

## What exists
- The viewer moves each top-level child of the GLB along `exploded.axis` by `spacing` times its rank
  (`report/viewer.js` `explode`); the assembly sheets do the same (`geometry/assembly.py`
  `exploded_scene`). `exploded: {axis, spacing}` is an assembly field (`core/model/assemblies.py:112-135`).
- A unit is placed in `model/geometry/<id>.py` either by coordinates (`place(...)`, 23 calls in the
  examples) or onto an interface (`place_by(I, res, iface_id, uri, built)`, 16 calls): then the child's
  frame is rotated and moved onto the placed party's frame along that frame's `normal`
  (`geometry/assembly.py:163-285`, `core/model/interfaces.py:83-94`). So for a `place_by` unit the
  direction it was pushed into place is already a known unit vector in the build.
- A unit placed by coordinates carries no direction. A GLB node carries `n2f_uri`, `n2f_node`, `n2f_kind`
  as `extras` (`geometry/glb.py:34-54,144-191`); extras need no schema bump (`docs/schema-policy.md`).
- Fasteners: in every example (table, test stand, kiln, bracket, enclosure) bolts, nuts and standoffs
  are `geometry: none`: they are counted and priced, but there is no bolt in the 3D model to pull out of
  a hole. Only modelled hardware (the kiln's hinges) is a 3D unit, placed by coordinates.

## Design
1. **Direction per top-level unit** (a part, or a sub-assembly that moves as one), in this order:
   a. *Placed onto an interface:* the interface frame's world normal, signed so it points from the
      party it was placed onto toward the unit. `place_by` records it on the `Placement` (it has the
      basis and the offset sign already).
   b. *Declared:* an optional `exploded.directions` map on the assembly, `{<child uri or label>: [x, y, z]}`,
      for units placed by coordinates whose direction the owner knows (a new optional field, no bump,
      no migration; absent for every existing product).
   c. *Otherwise:* away from the assembly's centre along the dominant axis of the unit's offset from it
      (so nothing moves through the model); a unit sitting at the centre moves up (+Z).
2. **Distance:** `spacing` (default 80 mm, as today) times a step that counts the units sharing the
   same direction line, nearest to the centre first, so two flanges on one side do not overlap. The
   slider factor 0..1 scales all moves; 0 is the assembled model, as now.
3. **Sub-assemblies move as one**; their own children are not exploded in v0.9 (as today: top level only).
4. **Where the direction travels:** a `n2f_explode: [x, y, z]` extra on the GLB group or instance
   (written by `geometry/glb.py` from the placement); `viewer.js` `explode(factor)` reads it per
   child and falls back to the old one-axis behaviour for a GLB without it. No format version change.
5. **Assembly sheets:** `exploded_scene` uses the same directions and steps, so the sheet's "pulled apart"
   picture matches the viewer's end of slider. This redraws every assembly sheet and the goldens that
   cover them (`make goldens REASON=...`).
6. **Files (expected):** `geometry/assembly.py` (Placement, `exploded_scene`), `geometry/glb.py` (extras),
   `core/model/assemblies.py` (the optional `directions`, one `core/` file; V12 expected 0 for M1, so this
   moves the count to 5 if the maintainer wants the field now), `report/viewer.js`, tests, goldens.
7. **Tests:** unit tests for the direction rule on a toy assembly (placed onto an interface; declared;
   fallback; two units on one line); a viewer test that a unit moves along its extra and that a GLB
   without extras still explodes; the sheet and the viewer agree on one example's unit positions.

## What this will not do (say so in the report's words, not silently)
- Pull bolts out of holes in the examples: they have no 3D geometry. Showing them would add new
  geometry (ghost cylinders from an interface's `spec.hardware` and the hole axis), which the plan lists
  as a non-goal.
- Reach inside enclosed units (the kiln's lining inside its shell moves along its fallback direction
  and passes through the shell unless the section cut is on).

## Questions for the maintainer (recommended answer first)
1. Bolts: leave fasteners out of the exploded view in v0.9, and file "draw fasteners in the exploded
   view" as a row; or draw ghost bolts now (new geometry, about a day more)?
2. Sheets: change the assembly sheets to match (recommended, one picture of the explode), or leave the
   sheets on the one-axis picture?
3. The `exploded.directions` field: add it now (recommended; it is the only way to fix a unit placed by
   coordinates, one more `core/` file), or ship with rules a and c only?
4. Fallback c for enclosed units: radial along the dominant axis is acceptable (recommended), or
   should an enclosed unit stay put until a direction is declared?

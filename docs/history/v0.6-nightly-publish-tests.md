# Nightly CI: bare-repository publish test failures

## Symptoms

The nightly `check-full` run fails with exit code 2 after the publishing push has apparently completed. The unit and end-to-end suites report failures in the two publish tests that inspect a temporary bare repository:

- `tests/unit/test_publish.py::test_send_online_to_a_bare_copy`
- `tests/e2e/test_publish.py::test_online_sends_to_the_online_copy`

A local reproduction of `make check-full` produced the same failures in the publish tests:

```text
2 failed, 1312 passed, 4 skipped
```

The remaining suite and its coverage floor pass.

## Root cause

The publishing implementation succeeds in pushing the `main`, `gh-pages`, and tag refs to the temporary bare repository. The test then queries the bare repository by using it as `cwd`, for example:

```python
subprocess.run(
    ["git", "rev-parse", "main"],
    cwd=remote,
    capture_output=True,
    text=True,
    check=True,
)
```

In environments that set Git's `safe.bareRepository=explicit`, Git rejects these reads. A bare repository is not considered safe merely because it is the current directory; it must be addressed explicitly.

The observed environment included:

```text
safe.bareRepository=explicit
```

The resulting error is:

```text
fatal: cannot use bare repository ... (safe.bareRepository is 'explicit')
```

A direct check confirmed that `git` pushes and creates the refs normally. The following same bare-repository reads fail under the restriction and pass when addressed with `--git-dir`:

```text
git -C <remote> rev-parse main       # rejected

git --git-dir=<remote> rev-parse main  # accepted
git --git-dir=<remote> tag --list      # accepted
```

The publishing code does not need a product behavior change: the push command is already responsible for writing the refs. The defect is in test setup that assumes ordinary bare-directory access.

## Proposed fix

Update the publish tests to inspect bare repositories explicitly with `--git-dir=<remote>` rather than setting the remote directory as `cwd`.

### Unit test helper

In `tests/unit/test_publish.py`, keep the existing `_git` helper for normal working repositories, and add a helper for bare repositories:

```python
def _bare_git(remote: Path, *args: str) -> str:
    return subprocess.run(
        ["git", f"--git-dir={remote}", *args],
        capture_output=True,
        text=True,
        check=True,
    ).stdout.strip()
```

Use `_bare_git(remote, ...)` for assertions about `remote`, for example:

```python
assert _bare_git(remote, "rev-parse", "main") == v.head()
assert _bare_git(remote, "tag", "--list") == "v1.0.0"
assert _bare_git(remote, "ls-tree", "--name-only", PAGES_LINE).split() == [
    ".nojekyll",
    "index.html",
]
```

The cloning step and every push from the normal product repository should continue using `_git`.

### End-to-end test helper

In `tests/e2e/test_publish.py`, change the local `git()` helper inside `test_online_sends_to_the_online_copy` to use the bare repository explicitly:

```python
def git(*args: str) -> str:
    return subprocess.run(
        ["git", f"--git-dir={remote}", *args],
        capture_output=True,
        text=True,
        check=True,
    ).stdout
```

This remains compatible with the existing assertions for tags, the branch log, and the `gh-pages` tree.

## Why this fix is appropriate

- It fixes the test rather than changing publishing behavior.
- `--git-dir` is portable across Git installations and is accepted by the relevant restriction.
- It does not disable repository safety settings.
- It preserves the test's coverage: the temporary remote can still be inspected for branch, tag, and pages refs.
- It makes the test correctly distinguish a normal product repository from its bare remote repository.

## Options not recommended

Do not remove or weaken `safe.bareRepository` in global or process configuration as a test workaround. That setting protects against accidental or untrusted bare-repository discovery.

Do not change the push implementation to avoid bare repositories. The `push --atomic` behavior is what this test suite is intended to verify, and replacing the bare remote with another repository type would weaken the coverage.

## Verification

After applying the test-helper changes, run the smallest relevant tests first:

```bash
uv run pytest tests/unit/test_publish.py::test_send_online_to_a_bare_copy -q
uv run pytest tests/e2e/test_publish.py::test_online_sends_to_the_online_copy -q
```

If both pass, run the publish test modules:

```bash
uv run pytest tests/unit/test_publish.py tests/e2e/test_publish.py -q
```

The local reproduction confirmed that both specific publishing failures pass when the tests use explicit `--git-dir` access while retaining the same environment configuration. The full-nightly gate was not completed here because the earlier reproduction stopped after the regular unit suite found these two failures.

## Scope

This is a test-infrastructure correction in the two publish test files. No source changes, dependency changes, workflow changes, or commits are required by the proposed fix.

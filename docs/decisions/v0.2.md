## S-056 — Version pin across 0.1 → 0.2 (D20): warn, never refuse `[revisit]` (2026-10-31)
`n2f build`, `n2f check`, `n2f status` and `n2f validate` compare the running version with
the product's `system` pin; a mismatch prints one dim line on stderr and **never refuses**
(D10's spirit: upgrading the tool must not lock a person out of their own product; the pin
says what the product was written for). `n2f doctor` shows the pin inside a product.
`schema: 1` is unchanged: v0.2 adds optional files only (`concepts/`, `style.yaml`, a
concept rule pack), so a v0.1 product loads untouched and needs no migration step; upgrade
migrations stay a non-goal until a schema change forces one. Templates and examples now pin
`>=0.2,<0.3`; `__version__` is `0.2.0` on `v0.2-build` from M0 (publishing happens only on
the `v0.2.0` tag, S-054). `[revisit]` if CI builds ever want a strict mode that refuses.

## S-057 — `n2f init` warms the CAD kernel in the background (2026-10-31)
The first `import build123d` on a machine takes one to two minutes with no output (B-0016).
`n2f init` now starts `python -c "import build123d"` as a detached process (own session,
no inherited streams) and exits at once, so the cost is paid while the owner reads the hint;
`n2f build` still prints its kernel note before its own import if it has to wait. Skipped
when build123d is already loaded in-process or `N2F_NO_WARMUP=1` (the test suite sets it in
`conftest.py`). `--json` reports `kernel_warmup`; the next-step line says the kernel is
warming only when a warm-up started. Code: `cli/kernel.py` (`load_cad_kernel` moved from
`build.py`, still re-exported there); the concept verbs reuse it from M1 on (N12).

## S-058 — `validate` reports expression errors alongside reference errors (2026-10-31)
Expression evaluation (cycles, unit mismatches) was skipped whenever any other error existed,
so the gate-3 kiln rework found thirteen bad expressions only after fixing references (B-0018).
Evaluation now runs whenever `parameters.yaml` parsed. Cascade suppression (S-012) narrows to
what it is for: a parameter that is, or transitively reads, one already reported (unsafe
syntax, unknown name, bad unit) is not re-evaluated, so each fault is reported once.
Fixture `tests/fixtures/invalid/expr-and-ref-together`; `EXPECT` lines after the second are
further substrings that must all appear in one run.

## S-059 — True plane section render (amends D12) (2026-10-31)
`section.png` is now a true plane section (B-0017): `render.clip_below` clips every triangle
exactly at Z = section_z (nothing above is drawn), and the cut faces are capped in image
space by back-face capping (viewer above the plane: nearest surface back-facing ⇒ the pixel is
inside a closed solid). Caps are drawn as part colour × 0.65, flat, with 1 px 45° hatch every
8 px at × 0.35 — flat shading alone collides with lit side faces; the hatch is the drafting
convention for cut material. Winding is normalised per mesh by signed volume; open meshes are
clipped but not capped and noted in `Scene.notes` (not yet surfaced: B-0019). Chosen over loop
chaining + triangulation (welding fragility) and OCCT half-space booleans (needs shapes at
render time, per-instance cost). Cost: the kiln assembly section renders in 0.8 s, less than
the full iso. **Judged:** the kiln section shows the shell as a thin red rim, the fiber as
wide hatched bands, the brick liner as a narrower hatched band and the chamber floor below,
with straight edges at the plane — against v0.1's sawtooth slivers. D12 now reads "an
isometric view and a true plane section (clipped, hatched caps)" in place of "a crude section".

## S-062 — Concept cards, loader and the optional Napkin stage (M1) (2026-10-31)
Cards (`core/model/concepts.py`) follow NAPKIN_STAGE §3; `envelope` takes a quantity or a
list of them, `site` keeps a value as a quantity when it parses, else as a word or yes/no
(`SA`, `240V-13A`, `outdoor: true`). Cards are keyed by file name; schema findings are rule
`C0-schema`, lint rules `C1-id-matches-file … C6-one-promoted` (C5 warns). `n2f concept new`
writes a commented skeleton (§3 order); `--from` copies six sections, not refs. Status edits
round-trip through ruamel with `explicit_null` so a reject is a two-line diff. Concept verbs
never load the product model (a half-written model never blocks ideas); ids accept `2`/`c-2`.
Reject records `{reason, at}`; on the promoted card it is refused (exit 3). Napkin gate:
present iff `concepts/*.yaml` exists, ok iff a card is promoted; later gates are computed
independently and `release` ignores it; the report calls `compute_stage(napkin=False)` so
concepts never reach a build output (N1). Bracket `status --json` golden pinned from bcd1451.
Two calls made here: (1) **napkin verbs do not snapshot** — ideas are cheap and a snapshot
per card is ceremony; `promote` (M4) snapshots, and `n2f status` already says "unsaved changes"
before a release. (2) A released product with a new exploring card reads **stage: Napkin** —
a new idea is a new iteration; the Released gate keeps its own result `[revisit]` if owners
find it confusing (gate B will tell).

## S-063 — Massing fidelity in the kit (N3) (2026-10-31)
`KitContext.fidelity: full|massing`; `kit.run` (and so the `Kit` namespace) dispatches to each
generator's `massing(args, ctx)`. It runs the *same* validation helper as `generate` (identical
error text, so an impossible composition fails for real) and builds primitives only
(Box/Cylinder, fuse/cut) in the full part's frame (bbox coincides within 0.05 mm).
plate/panel/block/hole_pattern: the outer box (no holes, cutouts or radii; an interface is
still resolved and checked, it never moves the plate). tube: the outer solid, no bore, sharp
corners. bracket_l: two leg boxes, sharp corner. enclosure: outer box minus the open-top
cavity (walls and base keep their thickness so mass reads right); **a flange is a feature:
the silhouette stays L × W × H**. frame: solid size × size member boxes at `pieces()`
positions, fused. Result: features `{process, extra: {fidelity: massing}}`, overall dims only,
no flat pattern or cut list, note "massing silhouette: features omitted". Golden
`tests/golden/goldens/massing.json` (volume/bbox per generator) recorded once.

## S-065 — Concept screening: computed vs estimate, the concept rule pack, red is information (N5) (2026-10-31)
`n2f concept build` composes a card's massing in-process (kit at fidelity massing, `at {x,y,z,rz}`,
GLB nodes `concept://C-xxx/<as>`) into `build/concepts/C-xxx/` — never in the manifest, no
`core.graph` import (N1) — then screens it. Every number is a `LabelledValue`: `computed` (bbox,
volume, mass when every call has a `material`, footprint with door swing) or `estimate` (calc kit;
`source` names the function). Missing inputs give a note, never a number. Rules:
`rulepacks/concept-v0.yaml` (S-022 shape, `applies_to: {scope: concept}`) run by
`concept_checks.run_concept_rules`; `fail` reddens, `warn` never; red is written to the card
with reasons and exits 0 ("this direction has problems:"). **Door-swing term:** for
`layout.door` hinged-left/right, `width + 1.0 × door_width ≤ site.alcove_width`, door width =
x-extent of the `door` call, else `envelope.door_width`, else 0 with a note (1.0 = the leaf swung
right back) `[verify]`. Defaults `[verify]` (from kiln parameters): room 25 degC, h 5 W/m²K,
ε 0.9, hot face 1200 degC; bare `insulation` = fiber board k 0.15 W/m·K, ρ 260, c 1050;
`brick`/K23 layers k 0.25, ρ 480, c 1000; circuit headroom 1.2; open-box blank (L+2H)×(W+2H),
bracket (L+H)×W, no edge margin; lift beyond two-person (33 kg) warns. The DEC-011 regression
card screens red for two reasons: the alcove with the door swing AND a one-piece shell blank
larger than any stock sheet — the shop read-through's lesson, mechanised. Two honest limits:
screening's heat-up at 2.5 kW is ≈ 4.4 h (the kiln's own calc 4.8 h) — DEC-004's 7 h is the
planned margin, not the calc, and the board must not suggest otherwise; the cost band is wide
(1423–4778 USD for the kiln-like card) because the cost tables span 8–68 USD/kg (B-0022).
Massing frames are solid boxes, so stand mass and welding cost are overstated (B-0021).
